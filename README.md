# Ace Bathroom Renovations Brisbane

Production marketing site for **Ace Bathroom Renovations Brisbane**, a QBCC licensed bathroom and kitchen renovation builder serving Greater Brisbane.

The site is deliberately simple and fast:

- **Static HTML**, generated by a small Node script. No framework, no runtime dependencies, no database.
- **One Cloudflare Pages Function** (`POST /api/quote`) for quote and contact forms.
- **Call-first conversion**: the phone number appears in the top bar, header, hero, sticky mobile bar, CTA bands and footer.
- **All CSS is inlined** in each page so styling arrives with the HTML. Only two self-hosted font files and the progressive-enhancement script are separate requests.
- **53 indexable pages plus a 404**, with 11 service pages, 13 suburb pages, 5 region hubs and a full internal-link directory.

## Requirements

- Node.js **20 or newer** (see `engines` in `package.json`)
- npm (only for the scripts; there are no production dependencies)
- A Cloudflare account for deployment

## Commands

| Command | What it does |
| --- | --- |
| `npm run build` | Rebuilds `dist/` from `src/`, including sitemap, robots, manifest, headers, redirects and routes. |
| `npm run check` | Runs the 12-point QA gate: links, schema, meta limits, link matrix, word counts, NAP rules, manifest, sitemap, 404. |
| `npm run serve` / `npm run preview` | Serves `dist/` at <http://localhost:4173>. The form endpoint returns a local-only fallback message. |
| `npm run test:api` | Tests the quote Function directly: validation, honeypot, unconfigured fallback and mocked delivery. |
| `npm run meta` | Prints the route, title and meta description for every built page. |

Typical local loop:

```sh
npm run build
npm run check
npm run serve
```

### Building for a different host

Canonical tags, Open Graph URLs, schema `@id` values, the sitemap and `robots.txt` are all
derived from `site.domain`. It defaults to `https://acebathroomrenovationsbrisbane.com`.
When the build is served from another host — for example the `*.pages.dev` project URL while
the custom domain is not attached — set `SITE_ORIGIN` so canonicals never point at a host
that does not resolve:

```sh
# PowerShell
$env:SITE_ORIGIN="https://ace-bathroom-renovations-brisbane.pages.dev"; npm run build

# macOS / Linux
SITE_ORIGIN="https://ace-bathroom-renovations-brisbane.pages.dev" npm run build
```

When the domain is attached, rebuild without the variable to restore the production origin.

## Editing content

### Business details (NAP, hours, phone, email)

Edit **`src/config.mjs`**. This is the single source of truth used by every page, the schema graph, `llms.txt` and the quote Function fallback copy. Change the phone, email, hours or domain there rather than in individual pages.

Three content rules are enforced by `npm run check`:

1. **The street address appears visually only on `/about/`.** The schema graph on every page contains the postal address for entity consistency, but the visible address block is limited to About.
2. **The QBCC licence number `17347609` and the QBCC verification link appear only on `/about/`.** They must not be added to the homepage, service pages or location pages.
3. **The owner/founder is never named.** Use "our team" or "we".

### Services and locations

- Add or edit a service in **`src/data/services.mjs`**. The build automatically adds the page, footer link, sitemap entry and schema.
- Add or edit a suburb or region hub in **`src/data/locations.mjs`**. Keep the local history, landmarks, housing notes and access constraints unique to each area.
- Register any new static page in **`src/data/pages.mjs`** *and* add its renderer to the `pages` array in **`build.mjs`**. The build fails if the registry and renderers disagree.

### Global styles

Edit **`src/styles.css`**. It is inlined at build time, so there is no separate stylesheet request and no flash of unstyled content. Keep the existing tokens (`--teal-900`, `--blue-600`, `--ink`, `--pale`) and mobile-first breakpoints.

### Images

All current imagery is **representative SVG placeholder art** in `public/images/`. Replace files with real photography using the same filenames, or update the paths in `src/config.mjs` and the page modules. Preserve:

- explicit `width` and `height` attributes to avoid layout shift;
- descriptive `alt` text (no keyword stuffing);
- WebP or AVIF where possible, with a sensible fallback;
- the Open Graph image at `public/images/og-image.png` (1200×630).

Gallery images are labelled as representative illustrations. Do not present them as completed client projects unless you have written permission and can supply the real project details.

### Metadata

Each page exports `title` and `description`. Keep titles at or below 60 characters and descriptions at or below 160 characters; `npm run check` enforces the limits. The canonical URL, Open Graph tags, breadcrumbs and schema are generated from the page path.

## Quote and contact forms

Both forms submit `multipart/form-data` to `POST /api/quote` with:

- a hidden honeypot field named `company_website`;
- shared status output in `#quote-status`;
- client-side validation plus server-side validation;
- a phone/email fallback if delivery is not configured.

The Function supports two delivery channels, used together when both are present:

| Variable | Required | Purpose |
| --- | --- | --- |
| `RESEND_API_KEY` | For email | Resend API key. |
| `QUOTE_TO_EMAIL` | For email | Destination inbox, e.g. `AceBathroomRenovationsBrisbane@gmail.com`. |
| `QUOTE_FROM_EMAIL` | For email | Verified sender on your Resend domain, e.g. `website@acebathroomrenovationsbrisbane.com`. Until that domain is verified, `onboarding@resend.dev` works but only delivers to the Resend account owner's inbox. |
| `QUOTE_WEBHOOK_URL` | Optional | JSON webhook for Slack, Notion, Zapier or a CRM. |

If no channel is configured, the endpoint returns **HTTP 503** with a clear call/email message rather than pretending the enquiry was sent. If delivery fails, it returns **502** with the same fallback. Submissions are not stored in a database.

Set these in **Cloudflare Pages → Settings → Environment variables** for both Production and Preview. See `docs/DEPLOYMENT.md` for the full procedure and Resend domain verification.

## Deployment

The site is designed for Cloudflare Pages with Git integration:

- **Build command:** `npm run build`
- **Build output directory:** `dist`
- **Functions directory:** `/functions` at the repository root

> **Important:** Cloudflare's dashboard drag-and-drop Direct Upload does **not** compile a `functions/` folder. Use Git integration or the Wrangler CLI from the repository root. See `docs/DEPLOYMENT.md`.

The generated `dist/_headers` sets security headers and long-lived caching for fonts and images. `dist/_redirects` handles the `www` canonical redirect and common legacy paths. `dist/_routes.json` limits Function invocation to `/api/*`.

## Quality gate

`npm run check` currently verifies:

1. Internal links resolve (0 broken).
2. JSON-LD parses with no errors or warnings.
3. Titles ≤60 and descriptions ≤160 characters.
4. Every non-legal page links to every other non-legal page.
5. Homepage ≥1,500 words.
6. Service and location pages ≥1,200 words.
7. Licence number only on About.
8. Street address visible only on About.
9. Owner name never published.
10. Manifest icons resolve.
11. Sitemap exists.
12. 404 page exists.

Additional manual checks used during delivery:

```sh
npm run test:api
node tools/qa-viewport.mjs    # 390px and 1440px overflow audit
```

Run Lighthouse against the built site before launch. The current build scores 100 for Accessibility, Best Practices and SEO on the homepage, a service page, a location page, the cost guide and About. Desktop Performance is 100 with first contentful paint around 0.31–0.38 seconds; mobile Lighthouse Performance varies with local CPU load (generally mid-80s to high 90s) and first contentful paint is around 1.2–1.7 seconds under Lighthouse's 4× CPU throttling. Styling itself is inlined in the HTML, so it does not wait on a stylesheet request.

## Content and compliance notes

- **No fabricated reviews, ratings, founding dates, project addresses or payment methods.** The reviews page explains the referee policy instead of inventing testimonials.
- **Cost figures are indicative planning ranges**, not quotes. The calculator rounds to planning ranges and states its assumptions.
- **QBCC details:** licence `17347609`, Builder Restricted to Kitchen, Bathroom and Laundry; Certificate III in Wall and Floor Tiling (CPC31320); Certificate III in Construction Waterproofing (CPC31420). These are published once, on About.
- **Address:** `63 Sedgebrook St, Spring Hill QLD 4000, Australia`. The business is mobile and works at client properties; the address is not a shopfront.
- **Hours:** 7:00am–10:00pm, seven days.
- **Placeholders:** SVG images are clearly representative. Replace them with real photography before presenting the gallery as completed work.
